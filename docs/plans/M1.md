## Design

### Themes (`packages/config/src/theme.ts`)

- **File:** `towns/<state>/<slug>.theme.json` sits next to the town YAML and is validated by a strict zod schema.
  - Fields as in §11a: `palette` (ink, accent, accentText, tint, surface, background), `type`, `masthead`, `layout`, `corners`, `motif`, `identityNotes`.
  - `towns:sync` stores it in a new `towns.theme` jsonb column.
- **Contrast checker:** every palette is checked against a fixed list of pairs the components actually use. A failing theme fails zod validation, so it can't be synced or merged ("cannot be saved").
  - **Text pairs (need ≥ 4.5:1):**
    - ink on background, surface and tint
    - accentText on accent
    - accent on background and surface (links)
  - **Fill only:** tint has no minimum, because it's never text.
- **Auto-adjusting a failing palette** is a launcher feature (§11a step 3), so it comes in M7.
- **Type pairings:** all 6 curated pairs are installed as `@fontsource` packages (self-hosted, no Google requests).
  - Their `@font-face` rules are always declared, but browsers only download the fonts a page uses. Each town downloads just its own pair.
  - A theme sets `--font-headline` and `--font-body`.
- **Corners:** `square | soft | round` set `--radius`.
- **Locked tokens:** the "Sponsored" label, byline and source-link styles come from fixed tokens a theme can't touch.
- **Default fallback theme:** a cool grey/blue palette with Literata / IBM Plex Sans, square corners and a `single-column` layout. It deliberately avoids the cream + serif + terracotta look §11a bans.

### Layout system (`apps/web/src/layout/`)

Each part is a component chosen by name from the theme. At least 2 options per part in M1:

| Part | Built in M1 | Later |
| --- | --- | --- |
| Header | `centered-masthead`, `left-logo-inline-nav`, `stacked-dateline` | `compact` |
| Navigation | `beat-tabs`, `hamburger-only` | `mega-menu`, `bottom-bar` |
| Grid | `single-column`, `main-right-rail` | `main-left-rail`, `split-two-column` |
| Article page | `classic-rail`, `wide-reading` | `magazine` (needs images, M4) |
| Footer | `three-column`, `minimal` | `community` |
| Directory | Schema accepts the values; templates are built in **M6** with the directory data (D-M1-2) | `list-map`, `category-grid`, `search-first` |

Rules enforced when a theme is validated or rendered:

- **Small towns:** a town with fewer than 5 items/day (using tier `small` until readiness scores exist) can't start its homepage with `lead-story`, and can't use `split-two-column`.
- **Newsletter on mobile:** `newsletter-cta` is always among the first two modules. If the theme's list doesn't put it there, the renderer inserts it.
- **Locked components** (byline, sources, Sponsored label) render outside any theme-controlled component.
- **Deferred to M7** (the generator):
  - the 50-mile neighbor rule; there's no town location data yet
  - layout experiments, and the `experiments` table that goes with them

### Slot contract (`apps/web/src/slots/`)

- **`<Slot name="home.top" />`:** reserves the slot's height up front (no layout shift) and runs the fill order from §11b:
  1. a `campaigns` row (the table is added in M1, empty)
  2. a sponsored placement (M6)
  3. programmatic (later, gated)
  4. a house ad
- **Slots in M1:**
  - `home.top`, `home.infeed`, `home.directory`, `home.events`
  - `rail.box`
  - `article.inline`, `article.related-businesses`
  - `article.realestate`, on property, permit and development beats only
- **Later:** directory slots come in M6 and newsletter slots in M5.
- **House ads in M1:**
  - "Advertise in {Site Name}", linking to `mailto:info@towncore.net`
  - a newsletter promo (see D-M1-1)
  - "Claim your free listing" starts once the directory exists (M6)
- **Labels:** paid units get the locked "Sponsored" / "Advertisement" label. House ads are labeled "From {Site Name}".
- **Ad-standards checks in e2e:**
  - every M1 slot renders on home and article, on mobile and desktop
  - reserved heights hold (no layout shift when a slot fills)
  - nothing sits between the headline and the first paragraph
  - mobile ad density on the test article stays ≤ 30%
  - labels are present

### Masthead and motifs

- **Masthead:** `packages/brand/src/masthead.tsx` renders an inline SVG wordmark from the site name, the headline font and the motif.
  - 2 styles in M1: `centered-serif` and `left-motif`.
  - Text stays live (`<text>` using the town's web font), so it's sharp and editable.
  - Converting text to paths, needed for favicons and OG images, waits until M4/M7, when those assets are generated.
- **Motif library:** `packages/brand/motifs/` holds single-color SVGs I draw by hand. M1 has 2: `palm-frond` for Boca and `lighthouse` for the dummy town. The full library comes in M7.
- **Rule check:** no city seal, official logo or government colors. Boca's palette is the §11a example (Atlantic blue / sea-grape green / stucco tint), not the city's branding.

### Pages

All built on the layout parts above, so each town's pages differ:

- **`/`** (home): the town's module list.
- **`/news/[slug]`** (article page): `classic-rail` or `wide-reading`. Contents:
  - headline and dek
  - byline from `buildByline()`
  - dates in the town's timezone
  - the body, as sanitized Markdown
  - a **Sources** box (locked style)
  - corrections
  - a "Report an error" link (`mailto:`)
  - `article.inline` after paragraph 3
- **`/about`, `/methods`, `/corrections`:** shared Markdown templates filled in with the town's details. You review the wording before production.
- **No `/network` page and no badge** (Rule 1 amended). TownCore appears only in the About page's publisher line, and on a Privacy page when one is added.

- **Boca test article:** a `[TEST]` article plus one test correction, from `pnpm db:seed:dev`. The seed refuses to run when `NODE_ENV=production` unless explicitly forced, and the town is `draft`, so it's `noindex` anyway.
- **Dummy town "Harbor Point":**

  It also asserts both still have bylines, sources and slots, and that no page except About mentions TownCore. Screenshots of both towns on mobile and desktop are saved as CI artifacts.
