## Where we start

**Already built:**
- **Town config:** a strict zod schema and loader, with `same_name_elsewhere`, `findTbdFields` ("a town can't go live until this is empty") and `syncTowns`, which never changes `status`. The `towns` table already has `census_id`, `tier`, `theme`, `status` and `readiness_score`.
- **Themes:**
  - Three style families (`coastal-modern`, `heritage`, `community`), type pairings, layout options and the module library.
  - A contrast checker that refuses a failing theme. It validates only; it doesn't adjust.
  - The content-volume rule (small towns can't lead with `lead-story`).
- **Brand:** 12 approved motifs, and an SVG masthead in 2 styles (`centered-serif`, `left-motif`). App icons and per-article share images are drawn from the theme.
- **Adapters:**
  - `SourceAdapter.detect()` on every adapter, and `findAdapter(url, html)`, already marked "for launcher discovery".
  - Platforms: `nws`, `civicplus`, `fl-dbpr`, `fl-sunbiz`, `page` (guides).
  - The Fetcher enforces Rule 8: robots.txt, Crawl-delay, 1 request a second, never-scrape list, documented-API allowlist.
- **Seeding pieces:**
  - evergreen guides (the story finder);
  - `seedDirectory` (Florida licenses);
  - `pnpm directory:stripe sync` (dry run by default);
  - `pnpm mail:onboard` (dry run by default);
  - the newsletter off → test → live switch.
- **Models:** a `launcher` model role (Opus in production).

**Missing:**
- The launcher itself: `pnpm launch`, `pnpm towns:rank`, `town_candidates`, any Census data use, name and domain checks, source discovery, readiness scoring, a theme generator, the neighbor rule (towns have no coordinates yet), a third masthead style, site-level identity assets, screenshot tooling, `launch-report.md`, `/admin/launches` and any code path that sets a town live.
- **The model layer:**
  - It has no web search and no image input. Discovery needs search, and the screenshot review needs images.
  - `callModel` needs a town for its spend caps, which a town that doesn't exist yet doesn't have.
- `docs/launch-friction.md` and `docs/town-rankings/`.

## Design

### 1. Choosing towns: `pnpm towns:rank FL [--near "Boca Raton, FL" --radius 60]`

- **Inputs, cached** in a new `place_data` table by source and vintage:
  - **Gazetteer:** incorporated places only.
  - **ACS 2024 and 2019:** population, households, income, owner share, growth.
  - **County Business Patterns 2023:** establishments in the high-value NAICS codes, via ZIPs.
  - **Coverage gap:** neutral until the Medill license arrives (D-M7-3).
  - **Cluster fit:** distance to live towns.
  - **Source readiness, light mode:** see §3. It costs model calls, so it runs only for the top 15 candidates.
- **Score:** the §10a weights, kept in config.
- **Hard filters:** population of at least 5,000, and readiness passing Rule 7 for the shortlisted.
- **Output:** a ranked CSV and a short report in `docs/town-rankings/<state>-<date>.{csv,md}`, plus `town_candidates` rows (`proposed`).
- **Approval:** in `/admin/launches` → Candidates, an admin approves or rejects each row (audited). **`pnpm launch` refuses a town without an approved candidate row.**

### 2. The launcher: `pnpm launch "Delray Beach, FL" [--domain x.com] [--approve-spend] [--resume]`

- **A run is a row in `launches`**, with one row per step in `launch_steps`. Steps are idempotent and resumable, like mail onboarding.
- **Dry run is the default:** nothing is bought, sent or deployed, and the town stays `draft`.
- **Outputs:**
  - `towns/<st>/<slug>.yaml`, `<slug>.theme.json`;
  - `docs/launches/<slug>/launch-report.md` with its screenshots and masthead options;
  - a line in `docs/launch-friction.md` for anything a person had to fix.
- **The steps (CLAUDE.md §10):**
  1. **Resolve:** Gazetteer match (state, incorporated), `census_id`, county, timezone, interior point, NWS zone, same-name places elsewhere (`same_name_elsewhere`), tier from population.
  2. **Names and domains** (§4 below). A purchase happens only with `--approve-spend` after you pick a name.
  3. **Discover sources** (§3).
  4. **Match adapters** with `detect()`. Unknown platforms become adapter requests (D-M7-7).
  5. **Readiness** (§3): stop if the town fails.
  6. **Seed** through the normal pipeline: 30 evergreen guides, recent meeting items, business backlog, and the directory where a state adapter exists (Florida only today).
  6b. **Theme, layout and identity** (§5), with 3 masthead options.
  7. **Provision:** Stripe test prices (`directory:stripe sync`), the mail domain (`mail:onboard`, dry run unless approved), the newsletter left `off`, and the Vercel project domain (dry run unless approved). Sitemaps and analytics need no step.
  8. **Write the launch report** (§6).
  9. **Leave the town `draft`.** An admin approves it in `/admin/launches` (§7).

### 3. Source discovery and readiness

- **Discovery:** the `launcher` model with web search proposes candidate URLs for each source kind: city site, agendas, meeting video, city news, police and fire news, schools, county permits and property, events.
  - **Code checks every URL before it counts:** robots.txt and the never-scrape list (Rule 8), one polite fetch, then `findAdapter()`.
  - The model suggests and code decides. A URL nobody fetched never enters a config.
  - Robots-blocked sources (Granicus, for example) are listed in the report as blocked and score 0, as decided 2026-10-15.
  - `--source kind=url` lets a person add or override URLs. Discovery runs without a model too, from those flags alone.
- **Readiness:** each matched source is ingested for the last 30 days into the draft town. The story finder then runs in **count-only mode** (classification and scoring, no writing).
  - Its accepted items per day, by source, is the readiness score: real items, not raw records.
  - Weather and guides don't count.
  - It must reach **3 a day (10 for `large`)**, or the launch stops with the reason (Rule 7). The score is stored in `towns.readiness_score`.

### 4. Names, domains and conflict checks (§10b)

- **Three names**, from the rotating patterns, with the neighbor rule: no pattern shared with towns within 50 miles. Each name gets:
  - **Domain:** `.com` availability and price (Vercel search, with RDAP as a cross-check).
  - **Archive history:** a domain with archive snapshots is checked for news-site history (titles and page text from a few snapshots, read by code with a model assist). Prior news use blocks the name (expired-domain abuse).
  - **Official-sounding words** (City of, Official, Gov, department names): blocked by code.
  - **Local outlets:** a name that matches or closely resembles a current or defunct local outlet found during discovery is blocked.
  - **Manual checks:** trademarks (a prefilled USPTO search link) and social handles go to the report as manual checks.
- **You pick one name in the report.** `--approve-spend` then buys it through Vercel with `expectedPrice` and the registrant contact from env.
  - The command shows the domain and price and needs a typed confirmation.
  - Every purchase is audited.

### 5. Theme, layout and identity

- **Visual identity:** the model writes `identityNotes` (landscape, architecture, signature places).
- **Proposed theme:** the model proposes family, palette, display face, motif, masthead style and a full layout, picked only from the existing option lists. The zod schema rejects anything else.
- **Code then enforces:**
  - **Contrast auto-adjust:** palette colors are moved in OKLCH lightness until every token pair passes AA. The theme schema still refuses failures.
  - **Content volume:** fewer than 5 items a day means `community` or a briefing-led front.
  - **Neighbor rule:** no shared family plus palette within 50 miles, and at most two shared of header, grid, article template and the first three modules. Towns get coordinates from the Gazetteer for this. The launch report shows the town beside its two nearest neighbors.
  - **The slot contract.**
- **Identity assets:** a third masthead style, so every town gets **3 masthead options**, rendered side by side for you to pick. From the theme, code draws:
  - a favicon;
  - a social avatar;
  - a default share image;
  - a newsletter header;
  - a Facebook cover (1640×624).
- **Screenshots:** a Playwright script renders home, article, directory and the newsletter on phone and desktop for the draft town, served locally with its seeded content.
- **Review pass:** the model looks at the screenshots against §11a. Its fixes are limited to theme fields and re-checked by code, and it runs at most twice. The final screenshots go into the report.

### 6. The launch report

`docs/launches/<slug>/launch-report.md` contains:

- **Automated checks**, each pass or fail:
  - Rule 7 readiness;
  - no TBD fields;
  - theme valid, AA and slot contract;
  - neighbor rule;
  - name checks;
  - a page that renders for every page type.
- **The town's details:** sources, with adapter coverage and blocked hosts; readiness by source; 5 sample stories (links on the draft site); the three name options with checks and prices; the masthead options; and screenshots beside the two nearest neighbors.
- **Failures.**
- **Manual to-dos:**
  - trademark search;
  - social handles;
  - Facebook page;
  - Google Publisher Center and Search Console;
  - first-batch guide review;
  - the mail domain once purchased;
  - Stripe live, when you decide.
- **AI cost of the run** (from `ai_usage`).

### 7. Going live: `/admin/launches`

- **Candidates:** approve or reject `town_candidates`.
- **Launches:** each run's steps, report and screenshots. **Approve launch** is admin-only and audited.
  - It refuses unless every automated check passes, the domain is ours and the mail domain is live. Rule 10: you approved the domain purchase and the production deploy separately.
  - Approving sets the town `live`. Schedules already run for draft towns, so live only changes indexing, publishing and sitemaps.
- **Pause** sets a live town back to `paused`.

### 8. Model use and cost

- **Launcher model:** the `launcher` role (Opus) for discovery and the theme.
- **Other roles:** routine (Haiku) for count-only readiness; writer and fact-check (Sonnet) for seeding.
- **Spend caps:** each launch gets its own cap (default **$25 a run**), logged in `ai_usage` under the draft town once step 1 creates it.
- **Development:** the Gemini development provider has no web search in our layer. Discovery needs the Anthropic key, or `--source` flags (D-M7-2).
- **Rough estimate per launch:** discovery $2–6, readiness $0.50–1, 30 guides $3–6, theme and review $1–3, so about **$7–16**. Checked on the first real run.
