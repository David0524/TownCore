## Bug found and fixed

The first contractor-license roundup listed "Construction Business Information, license QB"
lines and said 5 licenses instead of 3. DBPR's QB rows register the company a licensed qualifier
works under; they have no license number. The finder now counts only rows with a license number
(`isIssuedLicense` in `packages/pipeline/src/templates.ts`), with tests.

## Third attempt (another session, same day)

- `GEMINI_API_KEY` was set, and the environment also routes `generativelanguage.googleapis.com`
  through a network secret that the proxy adds to each request.
- Every call failed before reaching a model: HTTP 401 `API_KEY_SERVICE_BLOCKED` ("API keys are
  not supported by this API") on `generateContent`, the Interactions API and even the model list.
  The result was the same with the session's key in the header, in `?key=`, and with no key
  (proxy only). This is a different failure from the second attempt's 403. It means the key
  that reaches Google has API restrictions that exclude the Generative Language API. That is
  typical of a Google Cloud console key restricted to other APIs, not a Google AI Studio key.
- Nothing was run against the database, so no rows changed. The previous pass's state still
  stands.
- Fix: create a key in Google AI Studio (or in the Cloud console, set its API restrictions to
  allow "Generative Language API"), and store it as the network secret / `GEMINI_API_KEY`. Or
  add `ANTHROPIC_API_KEY`. Then start a new session.

## Found in the published roundups: mailing city is not city limits

The new-business roundup includes ZIPs 33428, 33496 and 33498: "Boca Raton" mailing addresses
that lie wholly or mostly outside the city. State records only give the mailing city, and
several ZIPs straddle the boundary, so a ZIP list wouldn't be exact either. Fixed by wording:
the roundups now say "with a Boca Raton mailing address" and note that such an address can be
outside the city limits. Exact city limits come with parcel lookups in M6.
